## Integrity rules

1. A stable requirement ID must map to exactly one acceptance criterion ID and planned test ID.
2. New/changed requirements require a corresponding SRS and RTM update in the same pull request.
3. Sources are explicitly split between initial instructions and analysis proposals; proposals are not owner-approved.
4. No placeholder evidence may be reported as a pass.
5. The approved status requires recorded reviewer, date, evidence and release gate completion.
